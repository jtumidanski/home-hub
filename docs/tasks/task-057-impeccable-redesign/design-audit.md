# Task 057 — Design Audit

## Method

Impeccable root: frontend/

- Root decided empirically (Task 1). With the config at
  `frontend/.impeccable/config.json`, `impeccable context` run from
  `frontend/` resolves `projectRoot` to `frontend/`, and `impeccable detect`
  run from `frontend/` honours the config's `overused-font: fraunces`
  ignore (probe file flagged without the config, not flagged with it). No
  automatic Impeccable hook was active in the session, so the hook path
  could not be exercised; the detector is the same config reader.
- `frontend/PRODUCT.md` written by `/impeccable:impeccable init` from
  design.md §2, with the user's confirmation of audience and contexts, tone
  and anti-references, and constraints (one round, all confirmed as
  written). The "references (loved)" row of design.md §2 was an unconfirmed
  guess and is visual direction, so it is not in PRODUCT.md.
- Shard audits (all run at task start, FR-12). Every shard was source-only: no page was rendered, so desktop/mobile/kiosk and light/dark judgements, and all contrast figures, are inferred from classes and OKLCH token values (estimates, not computed ratios) and are to be confirmed in the owning stage's render.
  - Shard a (`components/ui`, `components/common`, `features/navigation`, `LoginPage`, `OnboardingPage`, `Error404Page`, toasts, dialogs/popovers/forms): source-only; detector not run.
  - Shard b (dashboard pages, `dashboard-designer`, `features/dashboards`, `features/dashboard-widgets`, kiosk): source-only; detector returned no findings.
  - Shard c (Meals, Recipes, Ingredients, Shopping, Wish list): source-only; detector returned no findings.
  - Shard d (Calendar, Tasks, Reminders, package overlay): source-only; detector returned no findings.
  - Shard e (Habits/Tracker, Workouts, Packages, Weather): source-only; detector returned no findings.
  - Shard f (Households, Members, Settings, Data retention): source-only; detector returned no findings.
- Decision `page-header`: needed (Stage 1). Login, Onboarding and ErrorPage hand-roll a `CardTitle text-2xl` heading and the shell has no shared title/description/actions pattern; `font-heading` (Fraunces) needs one component to apply it.
- Decision `empty-state`: needed (Stage 1). `DataTable`, `LoginPage` and `ErrorPage`/`ErrorCard` each hand-roll a muted paragraph or icon+headline+body.
- Further primitive: `status-banner` (inline alert: icon + text + live-region role, replaces `ErrorCard` and the red-text-only Login error). Added as a Stage 1 finding row for Task 12.
- Routes audited with no findings: `/app/workouts/taxonomy` (`WorkoutTaxonomyPage`, beyond the shared page-header pattern). Redirect-only routes (`/`, `dashboard`, `tracker`, `shopping`, `workouts` index, `workouts/summary`) render no UI of their own; `DashboardRedirect` and `RedirectSummaryToReview` are covered by shard b and shard e respectively.
- Merge: 140 shard rows plus the `status-banner` row, numbered by Stage, then severity (P0 to P3), then shard letter. No rows were merged: the one shared Location (`frontend/src/pages/HouseholdMembersPage.tsx:216,266`, DA-034 and the Members icon-button row) describes two different problems (target size vs accessible name).
